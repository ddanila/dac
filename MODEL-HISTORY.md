## Runtime preservation and replay

Before replacing a core, preserve its JS/WASM and notices under
`public/emulator/archive/<wasm-sha>/`, add the pinned JS hash to
`src/archived-cores.json`, and run the preserved-state test. Restoration uses a
compatible archived runtime; it does not convert an old internal state layout.
The active runtime and archived catalog are authoritative, not a version list here.

Build the native replay runner with
`make -C ../dac-emulation build/dac-replay`, then run:

```sh
node scripts/replay-native.mjs path/to/session.dacrecord
```

This compares native C output with browser-recorded output. A `.dacrecord` is a
versioned command/media format, not a C structure dump. Equal output hashes are
regression evidence, not proof of every internal state or hardware timing.

## Reference keyboard mapping

`src/s600-paste.json` is generated by `scripts/s600-keymap.c` against the core's
Robotron, keyboard, SIO, Z80, media and trace objects using the reference S600 ROM.
The tool boots a fresh keyboard for each contact/modifier observation; it does not
infer characters from specimen legends. See the
[reference workflow](docs/robotron/capability-history.md#keyboard-mapping) for the
corresponding audit and identity boundary.

## Model changes

Edit canonical CAD, retain source provenance, regenerate affected meshes and
review both sides before syncing museum assets. Follow the
[keyboard controller workflow](docs/robotron/keyboard-controller-progress.md) for
its KiCad/OpenSCAD/core dependencies. Photo-derived geometry, mechanical estimates
and electrical assignments are separate claims. Visual approval never changes a
part's physical printed-and-verified status.

CI selection and duration estimates live in `scripts/ci-scope.mjs`, workflow files
and their data. Preserve conservative fallback coverage; do not copy run IDs,
shard timings or test inventories into this guide.
